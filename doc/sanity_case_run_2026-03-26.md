## Issues Found and Fixes

### 1) `make clean` fails on `.vdb` directory
- Symptom:
  - `rm: cannot remove 'simv.vdb': Is a directory`
- Fix:
  - Update `sim/Makefile` clean rule:
    - keep `rm -f *.vpd`
    - change `rm -f *.vdb` -> `rm -rf *.vdb`

### 2) Stimulus can start while DUT reset is active
- Symptom:
  - Early bytes can be dropped or miscompared in scoreboard.
- Fix:
  - In `sim/tb/uart_driver.sv`, gate drive start on reset release:
    - `wait (m_vif.i_rstn === 1'b1);`
    - then wait one clock before fetching sequence items.

### 3) Sanity test drain time too short
- Symptom:
  - Not all serialized bytes are observed before test drops objection.
- Fix:
  - In `sim/tb/uart_sanity_test.sv`, increase drain window:
    - `repeat (100)` -> `repeat (300)`

### 4) `make sim` did not fail on runtime UVM errors
- Symptom:
  - `simv` exits `0` even with `UVM_ERROR`, causing false pass.
- Fix:
  - In `sim/Makefile`, add post-log gate on `logs/$(TEST).log`.
  - Use `awk` pattern that catches real runtime `UVM_ERROR/UVM_FATAL` lines but ignores summary line `UVM_ERROR : 0`.

## Lessons Learned
- For UART/UVM smoke tests, reset gating in driver and adequate drain time are mandatory.
- Make targets should enforce pass/fail semantics from logs, not only process exit code.
- Cleanup targets should tolerate mixed file/directory artifacts generated by EDA tools.
